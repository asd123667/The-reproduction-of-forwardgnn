### 1.2 “无反向传播”的边界必须说清

ForwardGNN 避免传统的跨层端到端误差反向传播，但官方 SF 实现仍在单个训练层内部执行 PyTorch 的 loss.backward()。它属于逐层局部学习，不能描述成“完全不用自动求导”。

因此当前目标分为：

1. **论文复现**：忠实运行 ForwardGNN，保留局部求导方式。
2. **联邦扩展**：让不同客户端执行局部前向学习，再研究聚合与图切分。
3. **严格不使用任何反向求导的算法扩展**：只有课题确实采用这一严格定义时才另立实验，替换局部更新机制。它不是本论文原方法，也不是首轮复现任务。

这一界定不妨碍现在进行论文复现，但汇报时应使用“避免端到端反向传播的逐层图学习”等准确描述。

## 二、先理解首个实验在做什么

CoraML 中一个节点是一篇论文，边代表引用关系，特征描述论文内容，标签是研究类别。节点分类是预测论文类别。

Single-Forward（SF）在图中增加每个类别对应的虚拟节点。训练节点根据已知标签连接相应类别节点；验证和测试节点不能根据其真实标签建立这些连接。

一次局部学习流程：

1. 当前 GNN 层在增强图上计算所有真实节点和虚拟节点的表示。
2. 将训练节点表示与每个类别虚拟节点表示做点积，得到分类得分。
3. 得分除以温度参数，计算交叉熵，仅更新当前层。
4. 用验证集选择该层最佳参数。
5. 计算该层输出，detach 后作为下一层输入，再训练下一层。
6. 推理时各层输出类别概率，累加后取最大值。对同一节点，概率求和与求平均的 argmax 相同。

两层 SF-GCN 的表示维度为“输入维度 → 128 → 128”；类别得分由节点表示和类别表示比较获得。作者 BP 基线则使用 PyG GCN，最后输出类别维度。不能将 SF 强行改成“输入 → 128 → 7”后声称仍忠实复现。

“Single-Forward”指其局部学习不需要 FF 那样的正负两套输入，既不表示整个训练只前向一次，也不表示局部优化不用 backward。

依据：论文第 3.2 节、公式 (6)、附录 C 算法 2；实现位于 src/forward_learning/nodeclass/gnn_sf.py。

### 3.1 必须保留的实现细节

- SF 的 epochs 是**每层**最多训练次数；两层最多约 2000 次局部更新，BP 的 1000 是整个网络的更新上限。相同 epochs 不等于相同更新量或耗时。
- EarlyStopping 的 patience=100 是连续无改善的**验证调用次数**，不是恰好 100 个训练 epoch；验证间隔为 2。
- SF 输入先做逐节点 L2 归一化，GNNConv 后使用 ReLU；每层拥有自己的优化器。
- SF 虚拟节点初始特征通过 nn.Embedding 生成后 clone().detach()，不是单独注册训练的类别参数；其输出表示会随 GNN 层参数变化。保存与重载时必须保留这些初始特征和增强图状态。
- --append-label none 会在参数处理时转换为 Python None；不会关闭虚拟类别节点。
- 默认 GNN_SingleForward-GCN 使用普通 GCNConv；不能因为仓库含 CachedGCNConv 就声称默认启用了传播缓存。
- 原 SF 脚本遍历到 4 层，并在每层结束写出该层数的结果；这不代表只研究了四层。初期直接指定两层即可。
- src/settings.py 定义 data/、datasplits/、results/。运行前明确目录权限和数据位置。

### 6.3 单机的数据流与保存边界

    数据与固定 mask
       ├─ BP：PyG 全网分类 → 全网损失与更新 → 验证选模型
       └─ SF：训练标签增强图

              → detach 表示 → 第 2 层局部训练及验证

       ↓

若补充模型重载功能，SF 不能只保存模型 state_dict 后重新随机生成虚拟节点。还应保存虚拟节点初始特征、增强图所需信息、数据/划分标识及参数。精确续训还需各层优化器、当前层/epoch 和随机数状态。重载验收比较的是**同一方法保存前后**预测一致，而不是 SF 与 BP 预测相同。

## 七、这次代码核对发现的具体注意点

| 注意点 | 影响 | 建议 |
| --- | --- | --- |
| SF Accuracy 为百分数，BP 为比例 | 可产生 100 倍误读，末尾打印的 % 不能作为依据 | 按代码来源统一为百分数，保留原值 |

## 九、与联邦学习课题的连接：后续研究，不计入原论文复现

原仓库没有服务器、客户端通信或 FedAvg。文件名 linkpred-fl.sh 中的 FL 指 forward learning，不能据此认定已经实现 federated learning。

### 9.1 优先尝试同步逐层聚合

相对容易解释的首个方案是：

1. 服务器确定当前训练层。
2. 各客户端共享当前层的全局初始化，前面已训练层保持固定。
3. 客户端在自己的子图上构建训练标签虚拟边，执行当前层局部更新。
4. 按本地有标签训练节点数加权聚合当前层参数，重复若干通信轮。
5. 固定聚合后的当前层，客户端重算并 detach 本地表示，再开始下一层。

这是拟研究的联邦化方案，不是论文已验证的算法。不应直接让各客户端独立贪心训练全部层后整体平均，并默认它必然有效。

### 9.2 联邦阶段必须另行定义的内容

- 图切分：是否删除跨客户端边、切边比例、客户端允许访问的特征和邻居；节点分配与非独立同分布设置。
- 全局类别编号：客户端缺失某类时如何保留对应类别节点，不能按本地类别数量重新编号。
- 虚拟节点初始特征：是否共享初始化，怎样影响客户端表示的一致性；第一版可固定同一初始化作为明确设计。
- 聚合对象：先聚合当前 GNN 层参数，不能把原实现中的非参数虚拟特征或中间表示误当作普通权重平均。
- 切换层及每轮聚合后：什么表示、图传播缓存需要重算；采用缓存算子时避免复用旧模型对应的过期缓存。
- 本地优化器状态：是否跨轮保留；各客户端状态不能意外共用。
- 验证与早停：用约定的客户端验证统计确定通信预算，不用测试标签决定虚拟边。
- 客户端资源：顺序模拟时一次只将所需客户端模型/图置于 GPU，区分单客户端峰值和模拟器总占用。
- 通信量：统计实际上传下载的参数张量字节；单机统计不等于实机网络时延。
- 严格无局部反传：如课题要求，另设计并验证替代局部梯度的算法，与原 SF 结果分开报告。

### 9.3 联邦原型验收

- [ ] 单客户端、一个聚合轮次在相同输入与优化器状态下与本地当前层训练一致。
- [ ] 用已知参数验证加权平均，例如权重 1、3，参数 2、6，结果为 5。
- [ ] 训练后一层时，前层参数冻结且表示不保留跨层梯度图。
- [ ] 3～5 个客户端能完成两层的训练和聚合，保存每轮指标及通信量。
- [ ] 在相同客户端划分下比较 BP-FedAvg 与拟议逐层 SF 联邦方案，并披露结构和训练调度差异。
- [ ] 将原论文结果、联邦扩展结果和严格无反传算法扩展分别列出。

### 12.2 阶段 A 的正确顺序

1. **官方代码原样短跑**：先不改算法，确认入口、数据下载、划分生成/加载、日志和结果保存。
2. **SF-GCN 核心实验**：CoraML，1～4 层，hidden=128；先 1 run smoke，再 5 个 split。
3. **BP-GCN 对照**：同数据、层数、hidden、划分、训练预算和停止规则；保留 BP 与 SF 的结构差异。
4. **Top-Down 消融**：分别运行 Top-to-Input 和 Top-to-Loss，禁止合并成一个笼统的 “TopDown”。
5. **FF 方法**：FF-VN、FF-LA 分开跑，检查正/负输入或标签追加规则。
6. **多骨干和五数据集**：按资源逐步扩展至 CiteSeer、PubMed、CoraML、Amazon-Photo、GitHub，以及 GCN/SAGE/GAT。
7. **链接预测**：独立使用 edge split、正负边和 ROC-AUC；不要套用节点分类的虚拟类别节点流程。
8. **统一汇总和论文对比**：按五个 split 报告 mean ± std，并按论文的显存口径和相对一层比例汇总。

### 12.3 Top-Down 两条路径必须如何验收

论文中的两种 Top-Down 不能只写成“以后加入上层信息”：

| 路径 | 实现要求 | 单独验收 |
| --- | --- | --- |
| Top-to-Input | 当前层输入拼接上一时间步的 immediate upper layer 表示；最顶层的 context vector 对训练节点用 one-hot 标签，对其他节点用 uniform 分布 | 检查输入维度、时间步更新顺序、同步/交替更新设置和层间无梯度 |
| Top-to-Loss | 上层表示只用于当前层损失/推理表示融合，不送入下一层输入；Merge 按论文定义作用于损失路径 | 检查损失输入、下一层输入没有误拼接，以及与 SF 的单变量差异 |
| 两者共同 | 上层表示来自上一时间步；当前计算 detach；每层仍是局部更新 | 输出方法名、配置和消融结果必须分开 |

首轮不应同时修改 Merge、更新顺序、context vector 和优化器。若代码默认只实现其中一条路径，另一条应标记为“尚未复现”，不能从文件名推断已完成。

## 十四、LR 与联邦阶段的目录隔离

由于 LR 代码不是本论文官方代码，建议单独放置：

```text
forwardgnn-main/
  forwardgnn-main/          # 阶段 A：官方 ForwardGNN，不改主结构
  extensions/
    lr_gnn/                  # 阶段 B：LR-GCN/LR-GAT 独立实现
    federated/               # 阶段 C：客户端、服务器、FedAvg
  reproduction/
    protocols/
      forwardgnn_paper.md
      lr_extension.md
      federated_extension.md
    results/
      forwardgnn/
      lr/
      federated/
    reports/
```

阶段 B 可以复用数据读取和评估工具，但 LR 更新器不能悄悄替换 ForwardGNN 的 `src/forward_learning`。阶段 C 应复用已验证的本地训练器，先写 BP-FedAvg，再写 Forward/LR-FedAvg。

## 十五、修订后的最终结论

当前项目应按以下顺序执行：

1. 先用官方仓库和官方划分复现 ForwardGNN，不把 LR-GCN + Cora 称为论文复现。
2. 最小通路从 CoraML + GCN + SF/BP 开始，但完整论文范围还包括 FF、Top-Down、五个图、三种骨干和链接预测。
3. 论文方法复现完成后，再把 LR-GCN/LR-GAT 作为独立方法扩展。
4. LR 或 ForwardGNN 单机协议稳定后，再设计图联邦学习。
5. 联邦阶段至少比较 BP-FedAvg、ForwardGNN-FedAvg 和 LR-FedAvg，并独立报告图切分、通信量、客户端内存、时间和精度。
6. 阶段 A、B、C 的结果、结论和代码边界必须保持可追溯。

本次建议真正改变的是项目叙事顺序：论文复现是 A，LR 是 B，联邦创新是 C。后续汇报按这个结构组织，能避免“自己的扩展实验冒充论文结果”的问题。
