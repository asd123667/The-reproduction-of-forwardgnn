## 一、目标与总体路线

课题最终目标是在联邦学习客户端上使用无反向传播方法训练图神经网络，在保持可接受预测性能的前提下降低训练内存消耗，并量化时间和通信代价。

首要任务是建立可信的单机实验。推荐路线：

> 核对论文与代码 → 准备环境和 Cora 数据 → 修复运行问题并验证估计器 → 短跑检查 → 单机 LR-GCN 与 BP-GCN 对照 → 小规模联邦模拟 → 内存和计算优化。

第一阶段以 Cora 引文网络上的节点分类为对象，使用两层 GCN。节点代表论文，边代表引用关系，节点特征用于描述论文，标签代表论文类别。模型根据节点及其邻居的信息预测类别。

第一阶段交付物：可重复执行的实验配置、代码修正记录、训练日志与模型，以及准确率、Macro-F1、峰值内存和训练时间对照表。

## 二、先区分两套参考方法

| 材料                                                                               | 方法                                                                          | 建议用途                           |
| ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- | ---------------------------------- |
| 本目录`gnn/lr_gcn_cora.py`、`gnn/lr_gat_cora.py`                               | 注入随机噪声，通过似然比（Likelihood Ratio，LR）方法手工估计参数更新方向      | 优先复现的无反向传播训练路线       |
| 本目录`ICLR-2024-forward-learning-of-graph-neural-networks-Paper-Conference.pdf` | ForwardGNN：逐层局部学习，包括 Forward-Forward、Single-Forward 和上层信号扩展 | 理解图上的前向学习；后续可作为对照 |
| 之前提供的`D:/创新实践/forwardgnn-main/forwardgnn-main`                          | 上述 ForwardGNN 论文对应实现，局部训练仍使用自动求导                          | 复现 ForwardGNN 论文结果时使用     |

两套方法不能混用实验数字。ForwardGNN 避免跨层端到端反向传播，但其局部更新不等于完全不使用反向求导。本次 LR 脚本中的 `net.backward(loss)` 是自定义函数，用于手工填写参数梯度；函数名本身不代表传统反向传播。

本目录当前未提供《One Forward is Enough for Neural Network Training via Likelihood Ratio Method》正文、依赖版本说明和 Cora 原始数据。应补齐正文及对应实验协议，再确定 LR 结果的论文对照目标。不能把 LR 脚本的结果直接与附带 ForwardGNN PDF 的数字对齐。

复现分为三个层级：

1. **运行复现**：程序能完成训练、评估和结果保存。
2. **方法复现**：实现与方法推导一致，训练有统计上可观察的效果。
3. **结果复现**：数据、划分、超参数、评估和计算预算与目标论文一致，获得可比较结果。

运行成功不等于论文结果已经复现。

## 三、现有代码的关键设置与待检查事项

### 3.1 代码中已经确认的设置

- GCN 入口：`gnn/lr_gcn_cora.py`；GAT 入口：`gnn/lr_gat_cora.py`。
- GCN 为两层，隐藏维度 32，输出类别数写死为 7，Adam 学习率为 0.001。
- 数据路径为相对路径 `cora/cora.content` 和 `cora/cora.cites`。
- 节点随机划分比例约为训练 70%、验证 20%、测试 10%，并分别截取对应子图。
- 邻接矩阵先在全图上加自环并进行行归一化，再取子图；取子图后没有重新归一化。
- GCN 的 `num_copies=100`，每次参数更新进行 100 次带噪声前向采样；GAT 的默认值为 1。
- 训练循环为 `50 × 500` 次参数更新，因此 GCN 默认约有 250 万次训练前向计算，另有验证计算。
- 代码包含增边、删边、翻转边及 DICE 扰动实验，这些属于后续鲁棒性评估。

“One Forward”不表示整个训练只计算一次前向，也不能据此推断默认代码每次更新只执行一次前向。

### 3.2 问题清单与处理原则

| 检查项             | 当前发现及影响                                       | 处理方案                                                                                   |
| ------------------ | ---------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 数据和输出路径     | 目录未附 Cora 数据；代码直接写入`result`           | 补齐数据，设置明确的数据和输出路径，创建输出目录                                           |
| 奇数节点与噪声配对 | 噪声按前后两半赋正负值，奇数节点时两半形状不同       | 用小图验证奇偶两类输入；依据论文确定正确采样方式，不随意删除节点                           |
| 配对采样语义       | 给不同节点赋相反噪声，不等同于对同一输入运行正负扰动 | 对照论文核对，不直接宣称实现了标准反向配对采样                                             |
| 自动求导记录       | 未显式关闭梯度记录，手工更新期间仍可能构建计算图     | 在确认估计器不需要自动求导后，对对应训练和估计过程使用合适的无梯度上下文；验证参数仍会更新 |
| 噪声尺度           | GCN 更新`noise_std`，但前向噪声没有乘该尺度        | 核对理论公式和目标分布；记录选择固定噪声还是学习尺度的依据                                 |
| 图上的估计公式     | 图传播使节点损失依赖其他节点噪声                     | 检查逐节点损失与噪声配对是否覆盖相关依赖；不能仅按独立样本公式推断正确性                   |
| 训练缓存           | 保存输入和噪声，清理字段与实际缓存字段存在不一致     | 检查引用生命周期与计算图，区分必要缓存和多余保留                                           |
| 验证模型选择       | 记录最优验证损失，但没有恢复最佳模型                 | 原始设置与规范评估分开记录；规范版本保存并恢复验证集选择的模型                             |
| 随机性             | 只显式固定部分数据划分随机性，标签映射使用集合       | 固定 Python、NumPy、PyTorch 等种子，保存划分和标签映射；记录映射规范化带来的变动           |
| 图归一化           | 全图归一化后取子图会改变子图行和                     | 忠实复现保留原行为；重新归一化作为单独实验，不能悄悄替换                                   |
| GAT 内存           | 实现构造所有节点对的中间张量                         | 先完成 GCN，后续再考虑稀疏 GAT                                                             |
| 鲁棒性评估         | 代码在归一化矩阵上实施部分结构扰动                   | 正式复现攻击结果前核对原始邻接、扰动预算和重新归一化协议                                   |

以上主要是静态检查结果。对实际报错、内存增长和准确率影响，需要通过运行验证。所有修改应记录原行为、修改原因、理论依据和结果影响。

## 四、具体实施步骤与验收标准

### 步骤 1：确定复现对象，建立实验记录

**操作：**

1. 将 LR-GCN + Cora 节点分类确定为首个实验。
2. 补齐似然比论文正文，定位 GNN 实验、噪声分布、梯度估计公式和采样设置。
3. 保留老师原始文件，在独立实验目录维护可运行版本。
4. 建立 `CHANGELOG.md` 和实验登记表，记录每次代码、配置和评估协议变动。
5. 若先前向学习论文的复现也有要求，将其作为独立实验，使用之前的 ForwardGNN 仓库。

**验收：**明确“使用哪个代码、对应哪个论文实验、比较哪个指标”；缺失信息单独列出，不填写未经确认的论文目标数值。

### 步骤 2：准备环境和数据

**操作：**

1. 记录操作系统、CPU、内存、GPU、显存和驱动信息，选择独立 Python 环境。
2. 安装并记录 PyTorch、NumPy、pandas、SciPy、scikit-learn、matplotlib、tqdm 等依赖版本。
3. 本次两个 LR 脚本未直接使用 PyTorch Geometric；不必为运行这两个脚本提前安装整套图学习库。
4. 获取 Cora 原始数据，保存来源及文件校验信息，检查节点数、特征数、类别数和引用 ID 是否匹配。
5. 标准 Cora 通常有 2708 个节点、1433 维特征和 7 类，但应以实际文件检查为准。Cora 与 CoraML 是不同数据版本。
6. 固定运行目录或显式数据路径，建立输出目录；保存节点划分和标签映射。

**验收：**依赖可以导入；数据能读取；特征、邻接和标签维度匹配；归一化后无 NaN/Inf；数据划分可重现。

### 步骤 3：核对估计器并做最小正确性验证

**操作：**

1. 把一次训练更新拆成前向计算、噪声生成、损失计算、LR 估计、Adam 更新五部分。
2. 修复路径和形状问题；涉及算法含义的修改须先核对推导。
3. 用小规模可控网络或小图，检查每个待训练参数是否获得有限的梯度估计并发生更新。
4. 在理论条件适用的小例子上，用大量 Monte Carlo 样本，将 LR 平均估计与同一带噪声期望目标的参考梯度或有限差分进行统计比较。参考计算可以使用反向传播，它仅用于验证，不是正式 LR 训练流程。
5. 不要求单次随机估计与普通无噪声 BP 梯度相等；比较时必须统一目标分布和噪声设置。
6. 检查关闭自动求导记录后能否正常训练，并检查缓存和手工梯度不再意外持有计算图。

**验收：**奇偶节点数均可处理；噪声尺度与估计公式一致；参数更新正常；关键公式有可解释的验证结果。若公式尚有疑问，不进入长时间训练。

### 步骤 4：短跑检查

**建议配置：**两层 GCN、隐藏维度 32；先运行 20～50 次更新，必要时临时将采样次数调整为 1～5。该配置只用于排查问题，不代表论文设置。

**操作：**

1. 先用一个种子跑通训练、验证、模型保存和加载。
2. 记录损失、梯度估计范数、参数变化、耗时和内存。
3. 验证准确率是否明显异常，是否只是预测单一类别。
4. 排查内存持续增长、损失无效或参数始终不变等问题。
5. 短跑暂时不执行末尾攻击评估，日志明确标为“干净图训练调试”。

**验收：**完成全过程并可恢复模型；无无效数值和明显内存异常。短跑中随机波动是正常现象，不要求每一步损失都下降。

### 步骤 5：建立匹配的 BP-GCN 基线

**操作：**

1. 使用相同数据划分、图处理、模型层数、隐藏维度和输出定义实现标准反向传播训练。
2. 保持激活函数、偏置、实际启用的 dropout 等结构设置一致，不能仅依据参数名判断某功能已经使用。
3. 分别记录必要的超参数选择过程，使用验证集选模型，测试集用于最终评估。
4. 比较相同更新次数时的行为，并补充相同时间预算或达到相近验证性能时的代价。
5. 若另加公开常见 GCN 配置作为参考，应标注其与匹配基线的差异。

**验收：**BP 基线稳定学习；两组差异主要来自训练更新方式；所有额外差异可追溯。

### 步骤 6：完整单机实验与结果分析

**操作：**

1. 恢复经核对的正式配置，先完成一个种子的完整训练，估算总运行成本。
2. 预实验可用 3 个种子；正式对照建议至少 5 个，若目标论文另有规定则按论文执行。
3. 记录 Accuracy、Macro-F1、峰值内存、训练总耗时、每次更新耗时、更新次数和前向次数。
4. GPU 实验在独立进程中测量峰值 allocated/reserved 显存，说明是否包含模型、数据、梯度和优化器状态；计时时进行适当同步。
5. CPU 记录进程内存峰值并说明测量方式，不能把 CPU 内存直接称为显存。
6. 原样运行结果、必要修复结果和主动优化结果分别保存，避免混淆。
7. 获得可靠基线后，才逐项研究采样次数、稀疏邻接等优化。

**验收：**获得多个种子的均值与标准差，明确内存收益、精度变化和时间代价；若未对齐论文，说明差异来源，不将其表述为严格结果复现。

### 步骤 7：扩展至联邦学习模拟

这一阶段属于课题扩展，不是现有两个 LR 脚本已经具备的能力。

**操作：**

1. 在单机上模拟 3～5 个客户端，先验证训练与聚合流程。
2. 定义图划分规则：第一版可让每个客户端仅访问自己的子图并忽略跨客户端边，保存客户端节点分配和切边比例。
3. 明确验证和测试时允许访问哪些节点、特征和边，避免训练与评估使用不同的可访问信息却不加说明。
4. 全局统一类别编号；每轮服务器下发同一模型，客户端执行固定本地更新，再按训练标签节点数量等预先规定的权重进行 FedAvg。
5. 明确优化器状态是否在客户端保留、聚合哪些参数、噪声尺度如何处理。
6. 先完成 BP + FedAvg，再在相同设置下接入 LR + FedAvg。
7. 记录客户端峰值内存、轮次耗时、总前向次数，以及上下行实际参数字节数；单机字节统计不等于实机网络时延测试。
8. 流程稳定后再研究类别分布不均衡、客户端数量及本地训练步数的影响。

**验收：**服务器与客户端状态更新可核验；得到同一图划分下的 BP/LR 联邦对照；能够区分图切分损失和训练算法损失。

## 七、复现完成后的优化顺序

1. **清理多余计算图和缓存**：首先确保实测内存反映 LR 方法应有的计算流程。
2. **邻接矩阵稀疏化**：降低图结构存储和聚合成本，验证数值与训练协议保持一致。
3. **调整采样数量与估计方差**：比较准确率、内存和时间，而不是单纯减少采样。
4. **参数子集或分层更新**：研究仅更新部分参数是否能减少估计成本，需要独立消融实验。
5. **联邦本地步数与参与策略**：分析计算和通信的平衡。
6. **GAT、大图与边缘设备**：在基础实验成熟后再扩展，避免初期叠加密集注意力和部署问题。

首轮复现成功的标准，是能够解释并重复得到实验结果，而不是必须证明 LR 在所有指标上优于 BP。如果内存降低但训练明显变慢，或特定设置下精度下降，这些同样是后续优化课题的重要依据。

## 九、建议的复现代码架构

### 9.1 设计原则

采用“共享数据处理、模型前向和评估，分别实现 BP 与 LR 更新器”的结构，降低两份 GCN 实现不一致对实验的影响。

先在独立副本中做必要的小修改并跑通，再逐步拆分。每次拆分检查固定参数、输入和噪声下的输出及更新。算法修复和结构整理分别记录，不在首次运行前同时重写全部代码。下面的文件、接口和命令均是建议设计，尚未实现。

```text
reproduction/
  README.md
  CHANGELOG.md
  requirements.txt
  configs/
    smoke_lr.json                # 调试配置
    bp_gcn_cora.json              # 匹配 BP 基线
    lr_gcn_cora.json              # 经核对的 LR 配置
    fed_bp.json                   # 联邦阶段再添加
    fed_lr.json
  data/
    raw/cora/                    # 不在训练过程中改写
    splits/                      # 划分、标签映射、客户端分配
  src/
    __init__.py
    config.py                    # 读取、校验和保存生效配置
    data.py                      # 读取、图处理和划分加载
    models/
      __init__.py
      gcn.py                     # 共享 GCN 层和前向计算
    estimators/
      __init__.py
      lr.py                      # 噪声采样和 LR 估计公式
    trainers/
      __init__.py
      bp.py                      # 一次标准 BP 参数更新
      lr.py                      # 多次采样累积后的一次更新
    evaluate.py                  # 统一评估
    profiling.py                 # 时间、内存、前向次数统计
    checkpoints.py               # 模型及必要状态保存、加载
    train.py                     # 单机入口与训练循环
    summarize.py                 # 多次运行结果汇总
    federated/                   # 单机复现后再实现
      __init__.py
      partition.py               # 客户端图划分与切边统计
      client.py                  # 复用 BP/LR 本地更新器
      server.py                  # 模型分发与 FedAvg
      run.py                     # 轮次调度和联邦评估
  checks/
    test_data.py                 # 数据与划分检查
    test_lr_estimator.py         # 估计公式的关键验证
    test_update.py               # 参数更新、缓存、重载检查
    test_fedavg.py               # 联邦阶段再添加
  runs/
    <实验编号>/
      config.json                # 实际生效配置
      environment.json           # 环境、硬件、代码及数据版本
      metrics.csv                # 逐步或逐次评估标量
      best.pt                    # 验证规则选定的模型
      last.pt                    # 最后状态，按需支持续训
      result.json                # 最终测试和资源统计
  reports/
    protocol.md
    data_check.json
    estimator_check.md
    comparison_protocol.md
    summary.csv
    reproduction_report.md
```

原始代码继续保留在本目录的 `gnn/` 中，作为核对来源。需要相应功能时再建立对应模块，不必提前实现联邦系统。

### 9.2 模块之间的运行关系

```text
配置 + 数据
    ↓
train.py：创建共享 GCN 和所选更新器
    ↓
每次训练更新
    ├─ BP：前向 → 损失 → 自动反向求导 → 参数更新
    └─ LR：带噪声前向 → 损失 → LR 估计
            → 多次采样累积 → 参数更新
    ↓
evaluate.py：按约定模式统一验证
    ↓
模型、日志、资源统计 → summarize.py 汇总结果
```

共享预测结构不意味着内部缓存必须相同。LR 的输入和噪声缓存按公式管理，不能提前丢弃仍需使用的信息。

### 9.3 各模块的输入、输出和职责

| 模块         | 输入                               | 输出或职责                                    | 关键约束                                             |
| ------------ | ---------------------------------- | --------------------------------------------- | ---------------------------------------------------- |
| 数据读取     | 数据路径、预处理规则、划分文件     | 特征 X、图 A、标签 y、节点索引和元信息        | 不在训练器中重新随机划分；显式保留全图与子图处理规则 |
| GCN 前向     | X、A、噪声开关和配置               | N × C 类别得分，以及 LR 按需使用的本次上下文 | 不在模型内部读数据或调用优化器                       |
| LR 估计器    | 本次上下文、规定形式的损失         | 待训练参数的梯度估计                          | 标量或逐节点损失由理论决定，不为接口方便改变公式     |
| BP/LR 更新器 | 模型、优化器、图数据、配置         | 完成一次参数更新并返回标量统计                | 统一 step 含义；LR 一步可含多次前向                  |
| 评估器       | 模型、允许访问的图、评估节点与标签 | Accuracy、Macro-F1、损失                      | 统一噪声开关及评估模式，不更新参数                   |
| 日志与统计   | 标量、计时、内存读数               | 持久化记录                                    | 不保存持有计算图的损失张量                           |
| 联邦客户端   | 服务器模型、本地图、本地配置       | 本地参数、权重与统计                          | 复用训练器，不另写 LR 公式                           |
| 联邦服务器   | 客户端参数和聚合权重               | 下一轮模型                                    | 明确参数、缓冲区、优化器状态及噪声尺度的处理         |

LR 一次更新顺序：清空梯度 → 逐次采样和前向 → 估计并累加梯度 → 按定义求平均 → 一次优化器更新 → 清理本次缓存。BP 自动求导应正常可用，不能为了 LR 而把共享模型永久全局禁用梯度。

### 9.4 原脚本如何拆分

| 原脚本部分                        | 建议位置                              | 迁移检查                                     |
| --------------------------------- | ------------------------------------- | -------------------------------------------- |
| `parse_data()`、`read_data()` | `src/data.py`                       | 数据顺序、归一化、划分和映射符合约定         |
| `Block`、`GCN` 前向           | `src/models/gcn.py`                 | 固定输入、参数和噪声下输出一致               |
| 噪声及自定义`backward()` 公式   | `src/estimators/lr.py`              | 忠实迁移与公式修复分别记录                   |
| `num_copies` 及梯度累积         | `src/trainers/lr.py`                | 平均系数、采样数和更新频率正确               |
| 训练、验证循环                    | `src/train.py`、`src/evaluate.py` | 验证时机、模型选择和预算明确                 |
| 模型、曲线及结果保存              | 检查点、日志及汇总模块                | 保存生效配置，评估可重现                     |
| 图攻击函数                        | 后续独立鲁棒性模块                    | 初期不作为常规训练必经步骤；攻击协议另行核对 |

### 9.5 建议运行入口和配置

实现后建议提供以下入口；目前命令尚不能直接执行：

```text
python -m src.train --config configs/smoke_lr.json
python -m src.train --config configs/bp_gcn_cora.json
python -m src.train --config configs/lr_gcn_cora.json
```

精确恢复训练还需保存优化器、随机数状态和当前步数；仅加载权重通常只足够进行评估。两种保存用途应区分说明。

## 十、汇报时如何描述进度

| 已完成范围            | 可以使用的表述                 | 还不能声称                     |
| --------------------- | ------------------------------ | ------------------------------ |
| 步骤 1～2             | 已明确目标并完成环境、数据准备 | 模型已复现                     |
| 步骤 3～4             | 更新实现通过检查，训练流程跑通 | 达到论文精度或稳定收敛         |
| 步骤 5～6 的初步条件  | 完成单机初步复现及 BP/LR 对照  | 全部论文结果已复现             |
| 步骤 6 的论文对齐条件 | 指定论文实验按约定标准复现     | 其他模型、数据和全部结论均成立 |
| 步骤 7                | 完成单机模拟联邦原型和对照     | 完成树莓派/手机实机及网络测试  |

验收以配置、日志、检查记录和可重复结果为依据。曲线好看、准确率超过任意指定数值，或仅仅没有报错，都不能单独代替上述证据。
