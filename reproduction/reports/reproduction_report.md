# ForwardGNN 复现阶段性报告

> 本报告面向第一次接触 ForwardGNN 的读者。建议先读第 1～3 节理解“实验在比较什么”，再读第 4～6 节看数据，最后读第 7～9 节确认复现边界和后续工作。

## 1. 先看结论

### 1.1 这次实验要回答什么问题？

本报告回答一个具体问题：在图节点分类任务中，ForwardGNN 的 **Single-Forward（SF，单前向）训练方式**，与普通的 **Backpropagation（BP，反向传播）训练方式**相比，能否保持相近的准确率，并减缓网络加深时的显存增长？

本次已经完成论文中的一组核心子实验：

> **CitationFull-Cora_ML 数据集 + GCN 模型 + SF/BP 对照 + 1～4 层深度扩展。**

### 1.2 当前可以得出的结论

1. 在 CoraML + GCN 上，SF 和 BP 的测试准确率与论文结果接近。8 组“方法 × 层数”配置与论文的差异均不超过 **0.57 个百分点（pp）**。
2. SF 的峰值显存随网络层数增加变化很小：本次测得相对于 1 层约为 **1.01～1.02 倍**。
3. BP 的峰值显存随层数增加明显：相对于自身 1 层，本次测得约为 **5.37～5.55 倍**。按扣除常驻输入显存的近似口径重算，约为 **19.86～20.62 倍**。
4. 因此，本次复现支持论文的核心趋势：**SF 在网络加深时显存增长较平缓，BP 的显存增长更明显。**

### 1.3 目前不能得出的结论

1. 这还不是整篇论文的完整复现。目前只完成 CoraML + GCN；其他数据集、SAGE/GAT、其他 Forward 变体和链接预测尚未完成。
2. 不能简单说“SF 的绝对显存一定比 BP 小”。在本次测量的 1～4 层中，SF 的绝对峰值显存都高于同层数 BP；已经验证的是 **SF 的显存随深度增长较平缓**。
3. 不能说 SF“完全不使用反向传播”或“完全不使用自动求导”。SF 避免的是跨层端到端的误差反传；每一层内部仍然使用局部损失和 `loss.backward()` 来更新该层参数。
4. 本阶段还没有开始联邦学习实验，因此不能据此声称无反向传播联邦学习系统已经完成。

上图横轴是“相对于该方法自身 1 层的显存倍数”，纵轴是准确率。SF 的点在不同层数下接近重叠，BP 在增加层数后明显向右移动。注意：两种方法各自使用不同的基准，SF 的 1 倍是 347.8 MiB，BP 的 1 倍是 45.3 MiB；**SF 的点更靠左不代表其绝对显存更低**。右面板的扣除输入口径仅是近似辅助分析，不能作为显存严格对齐的证据。

## 2. 用白话理解本次实验

### 2.1 GCN 模型是什么？

本实验使用 GCN（Graph Convolutional Network，图卷积网络）处理引用网络。每篇论文是一个节点，论文之间的引用关系是边，论文的词袋特征是节点输入，论文所属主题是分类标签。

模型的任务是：根据一篇论文自身的特征和邻居论文的信息，预测它属于哪一个类别。

“1 层、2 层、3 层、4 层”可以粗略理解为信息传递的范围：

- 1 层：节点主要聚合一跳邻居的信息；
- 2 层：信息可以间接来自两跳邻居；
- 层数越深：理论上可以看到更远的邻居，但训练时通常也会保存更多中间激活值。

更深并不一定更准：邻居信息也可能被过度混合，所以需要实际比较不同层数的结果。

### 2.2 BP 和 SF 在比较什么？

**BP（普通反向传播）**：先完成整个多层 GCN 的前向计算，得到预测结果和损失，再从最后一层向前计算梯度，统一更新所有层。为了计算这些梯度，训练过程通常需要保留多层中间激活值，所以模型变深时显存压力会增加。

**SF（Single-Forward，单前向）**：把多层网络拆成逐层的局部学习过程。每一层用当前层的输入表示计算自己的局部目标并更新自己的参数，然后把输出表示 `detach` 后交给下一层。这样后面的层不需要通过计算图把梯度传回前面的层，减少了跨层保存和反传的需要。

“局部目标”来自哪里？SF 在图中额外加入 7 个虚拟类别节点，可以把它们理解为 7 个类别的“代表”。只将有训练标签的节点连接到其对应的类别节点。在当前层的一次前向计算中，真实节点和类别节点都得到新的表示，再比较它们的匹配程度，用正确类别计算分类损失。

以两层网络为例，代码的工作顺序是：

```text
原图 + 虚拟类别节点
        ↓
训练第 1 层：计算当前层表示 → 局部损失 → 只更新第 1 层
        ↓
恢复第 1 层的最佳验证状态，生成并 detach 输出表示
        ↓
训练第 2 层：用第 1 层的固定输出 → 局部损失 → 只更新第 2 层
        ↓
推理时将两层的类别概率相加，选择概率和最大的类别
```

“Single-Forward”不等于“整个模型只运行一次就训练好了”，而是当前层不需要额外的负输入图前向计算。每层仍然要重复训练多轮。

这里的“无反向传播”应准确理解为：**不进行跨所有层的端到端反向传播**，而不是代码中完全没有梯度计算。

### 2.3 本次实验比较哪些指标？

这组实验想回答两个问题：

1. 模型能不能学会分类？用测试集 Accuracy（准确率）衡量。
2. 网络变深时训练需要的显存会不会快速增加？用独立进程测量的峰值 GPU 显存衡量。

准确率表中的“均值 ± 标准差”来自 5 个官方数据划分。标准差越小，说明不同划分之间的结果波动越小。

例如 `88.11 ± 1.22%` 表示 5 次测试准确率的平均值是 88.11%，标准差是 1.22 个百分点；它不是保证每一次都落在这个区间内。`pp` 表示“百分点”：88.11% 减去 86.88% 是 1.23 pp，不是相对提高 1.23%。

### 2.4 常见术语速查

| 术语 | 在本实验中怎么理解 |
| --- | --- |
| 参数 | 模型需要学习的权重，不是输入数据本身 |
| 节点表示 / 激活值 | 当前层为节点算出的特征向量；是模型运算的中间结果 |
| 损失 | 衡量预测与正确标签差多少的数值，用于指导参数更新 |
| detach | 切断梯度追踪，保留数值；不是删除这个向量 |
| epoch | 一轮训练；SF 与 BP 的轮数含义存在差别，见 §3.3 |
| split | 一套训练、验证、测试节点的划分方案 |
| 训练 / 验证 / 测试 | 训练集更新参数，验证集选状态和早停，测试集报告最终效果 |
| 显存 | GPU 上的存储空间，不等于 CPU 内存，也不等于训练速度 |

## 3. 复现对象、数据和判定标准

### 3.1 复现对象

| 项目 | 内容 |
| --- | --- |
| 论文 | ICLR 2024，*Forward Learning of Graph Neural Networks* |
| 官方实现 | `facebookresearch/forwardgnn` 的代码快照，本仓库进行了逐文件 SHA-256 校验 |

| 扩展目标 | 在同一设置下测试 1～4 层，并测量显存随深度的变化 |
| 方法 | SF（单前向）与 BP（反向传播） |

### 3.2 数据集和划分

本次使用 CitationFull-Cora_ML：

- 2,995 个节点；
- 2,879 个节点特征；
- 7 个类别；
- 16,316 条有向边记录，与论文 Table 2 对齐；
- 使用官方提供的 5 组数据划分，比例为 64% 训练、16% 验证、20% 测试。

数据审计确认的是：**每一个 split 内部** 的训练集、验证集和测试集互斥，并覆盖全部节点。不是说不同 split 的训练集互斥。每个 split 都完整运行一次，最后对 5 个结果求均值和标准差。

### 3.3 训练协议

| 项目 | 设置 |
| --- | --- |
| 隐藏维度 | 128 |
| 优化器 | Adam |
| 学习率 | 1e-3 |
| 权重衰减 | 5e-4 |
| 最大训练轮数 | 1000 epochs |
| 验证频率 | 每 2 个 epoch 验证一次 |
| 早停 | patience=100，按验证次数计 |
| 重复次数 | 5 次，对应 5 个官方 split |
| SF 温度参数 | τ=1.0 |
| SF 虚拟节点边 | 双向连接 |

`run_i` 对应 `split_i`，种子为 `100 × 101 + run_i × 3`，即 10100、10103、10106、10109、10112。它们不是在同一个固定划分上仅更换种子的 5 次运行。

还需注意训练预算：BP 是全网最多 1000 次更新，SF 是**每层**最多 1000 次局部更新，并且每层独立早停。因此“epochs 参数相同”不代表更新量或训练时间相同，本报告不据此宣称 SF 更快。

### 3.4 事先约定的“对齐”标准

为了避免看到结果后再改变标准，本次提前约定：

- 与论文均值相差不超过 1.0 pp，且落在论文均值 ±2 倍标准差范围内：记为“与论文一致”；
- 相差 1～3 pp：记为“趋势一致”；
- 相差超过 3 pp：记为“未对齐”。

这是本项目预先约定的复现验收标准，不是严格的统计显著性检验，也不等于两种方法完全等价。

### 5.2 如何理解准确率结果？

- BP 的 1 层结果只有约 32%，与论文的一层结果一致，不能单凭这个低值认定代码出错。具体原因还需结合一层和多层模型的结构、表示能力等分析，不能仅凭这张表归因于感受野不足。
- 增加到 2 层后，BP 准确率提升到约 87%，说明本配置中两层模型明显优于一层模型；这不证明继续加深一定有收益。
- SF 在 1～4 层都保持在约 87.5%～88.3%，说明在当前任务上没有因为采用逐层训练而明显损失分类性能。
- 不能写成“SF 在 2～4 层都高于 BP”：实际情况是 L2 和 L4 的 SF 高于 BP，L3 的 SF 略低于 BP。更准确的表述是：**两种方法在 2～4 层的准确率总体接近，SF 在部分层数上略高。**

具体差值（SF 减 BP）：L2 为 +1.23 pp，L3 为 -0.43 pp，L4 为 +1.13 pp。这是均值比较，尚不能据此宣称统计上显著优于 BP。

## 6. 结果二：显存是否随层数增长？

这一节看“训练模型需要多少 GPU 显存”。显存单位是 MiB（1 MiB = 2²⁰ 字节）。`mem_wrap.py` 对每种配置在独立进程中记录 `torch.cuda.max_memory_allocated()`：即该进程中 PyTorch 张量占用显存的峰值，不是 `nvidia-smi` 显示的整个进程总显存，也不包含全部 CUDA 上下文开销。

准确率是 5 个 split 的均值 ± 标准差；显存则是包含这 5 次运行的进程峰值，**不是 5 个峰值的平均数**。由于硬件、软件和测量口径不同，本机绝对值不用于与论文的绝对值直接对齐。

### 6.1 峰值显存表

| 方法 | 指标 | L1 | L2 | L3 | L4 | 论文 Table 4(e) |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| BP | 峰值（MiB） | 45.3 | 243.3 | 244.1 | 251.3 | 0.83 / 7.99 / 10.07 / 12.58 MB |
| BP | 相对自身 1 层 | 1.00× | 5.37× | 5.39× | 5.55× | 1× → 约 15× |
| BP | 修正口径* | 1.00× | 19.86× | 19.93× | 20.62× | 仅作近似对照 |
| SF | 峰值（MiB） | 347.8 | 351.4 | 352.2 | 353.0 | 41.56 × 4 层（恒定） |
| SF | 相对自身 1 层 | 1.00× | 1.01× | 1.01× | 1.02× | 约 1×（恒定） |

`* 修正口径` 是扣除常驻 GPU 输入的估算大小后重新计算的近似比例，脚本中 BP 扣除 34.8 MiB，SF 扣除 35.0 MiB。论文没有完全公开显存测量细节，因此这个比例不能称为严格复现论文口径，只能作为辅助比较。BP 的一层峰值扣除输入后只剩约 10.5 MiB，分母变小会放大比例，也使比例对输入估算误差更敏感。

### 6.2 如何理解显存结果？

本次结果支持以下更精确的说法：

- SF：从 1 层增加到 4 层，峰值显存从 347.8 MiB 变为 353.0 MiB，变化很小；
- BP：从 1 层增加到 4 层，峰值显存从 45.3 MiB 变为 251.3 MiB，增加明显；
- 在本次测量的 1～4 层中，SF 的绝对显存都高于同层数 BP，但 SF 的显存曲线更平坦；
- 因此本次支持的主张是 **“显存随深度的增长更平缓”**，不是“任何数据规模、任何层数下 SF 的绝对显存都更低”，也没有验证在更深层数或大图上 SF 与 BP 的显存交叉点。

![显存随深度变化](image/reproduction_report/1790174385943.png)

### 6.3 为什么 SF 的显存增长较平缓？

BP 要把整个多层计算图连接起来。为了最后计算梯度，训练期间通常需要保留从前面各层到后面各层的中间激活；层数增加后，保留的跨层信息也会增加。

SF 的实现把每一层作为局部训练单元。当前层更新完成后，传给下一层的表示被 `detach`，不再携带前一层的梯度计算图。因此后面的层不需要保留一条贯穿所有层的端到端反传路径。本次实验中观察到的“SF 显存随深度变化较小”，正是这种训练组织方式在显存上的表现。

这里的解释是对实现机制的概括，不等于声称所有中间张量都会立即释放，或显存必然只与单层有关；实际峰值还会受到参数、优化器状态、输入图和 PyTorch CUDA 内存分配器的影响。

## 7. SF 方法实现检查：为什么可以相信代码确实按论文方式运行？

除了看最终准确率，还对 SF 的关键行为做了静态源码检查和动态断言，共 **18/18 项通过**。动态检查使用 CoraML、split 0、2 层 GCN、每层 2 个 epoch 的最小配置；这是机制检查，不是对全部配置的穷尽测试。主要证据如下：

1. **增强图正确**：原图有 2,995 个节点，增加 7 个虚拟类别节点；虚拟边共 3,832 条，即训练节点数的 2 倍，表示使用双向边。
2. **类别边未使用验证/测试标签**：每个训练节点只连接自己类别的虚拟节点，验证节点和测试节点不添加类别边。这一检查针对虚拟类别边，不等于审计了所有可能的泄漏路径。
3. **局部分类目标正确**：logits（分类打分）使用节点表示与类别代表表示的点积，与手工展开的最大差约为 1.49e-08；再计算交叉熵，温度参数为 τ=1.0。
4. **层间参数隔离**：不同层使用互不相交的优化器参数集合；训练第 2 层时，第 1 层参数的 SHA-256 逐比特不变。
5. **没有把梯度图传给下一层**：传给下层的表示满足 `requires_grad=False`。
6. **推理方式正确**：使用各层类别概率进行融合，覆盖全部层的输出。

需要准确理解“点积”：它用于衡量节点表示与类别代表表示的匹配程度，同时受向量方向和长度影响，不能简单称为“纯方向相似度”。

“不需要负样本”也容易被误解。这里的含义是：不需要额外构造一个负输入图；其他类别仍然作为交叉熵分母中的对比类别参与分类。

## 12. 常用复现实验命令

以下命令在 WSL 的运行副本 `~/forwardgnn-run/src/` 中执行。相同 `--exp-setting` 下已经完成的运行会被跳过；需要重测时使用 `--overwrite-result`。

```bash
source ~/miniconda3/etc/profile.d/conda.sh && conda activate ForwardLearningGNN
export CUBLAS_WORKSPACE_CONFIG=:4096:8

# 两层 BP：5 个官方划分
python train_backprop.py --task node-class --model GNN-GCN --dataset CitationFull-Cora_ML \
  --num-layers 2 --num-hidden 128 --num-runs 5 --seed 100 --epochs 1000 --val-every 2 \
  --patience 100 --lr 0.001 --gpu 0 --exp-setting paper-bp-coraML-L2-v1

# 两层 SF：5 个官方划分
python train_forward.py --task node-class --model GNN_SingleForward-GCN --dataset CitationFull-Cora_ML \
  --num-layers 2 --num-hidden 128 --num-runs 5 --seed 100 --epochs 1000 --val-every 2 \
  --patience 100 --lr 0.001 --gpu 0 --append-label none --aug-edge-direction bidirection \
  --temperature 1.0 --exp-setting paper-sf-coraML-L2-v1

# 完整显存测量示例：两层 BP
# 若此配置已有结果，本命令会跳过训练；不要把跳过后的显存当作新测量结果。
python mem_wrap.py train_backprop.py --task node-class --model GNN-GCN \
  --dataset CitationFull-Cora_ML --num-layers 2 --num-hidden 128 --num-runs 5 \
  --seed 100 --epochs 1000 --val-every 2 --patience 100 --lr 0.001 --gpu 0 \
  --exp-setting mem-bp-coraML-L2-v1

# 汇总：读取运行副本的 results 目录，生成其中的 resource_summary.csv
python3 ~/forwardgnn-run/src/summarize_resources.py
```

确需覆盖旧结果重新训练时，才在训练命令末尾加 `--overwrite-result`。深度实验要同步修改层数和 `--exp-setting` 中的 `L2`，SF 测量则使用 `train_forward.py` 和对应的 SF 参数；完整命令以 `experiment_registry.md` 和协议为准。
